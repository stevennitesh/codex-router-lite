# LiteLLM 1.102.1 compatibility refresh - 2026-09-23

Historical dependency-review evidence, not live installation status. Current
dependency authority remains `requirements/python.in`,
`requirements/python.txt`, and `src/install-plan.mjs`.

## Change

Router Lite reviewed and upgraded its LiteLLM proxy pin from 1.96.2 to 1.102.1.
The Windows CPython 3.10 hash lock was regenerated from the maintained compile
command. The resolved closure contains 111 distributions and retains FastAPI
0.139.2 as the separately pinned, known-good gateway pair.

The candidate was installed into a disposable CPython 3.10.19 virtual
environment and the real LiteLLM proxy was booted on Windows. No live Router
runtime, provider credential, or billable provider endpoint was used.

## Compatibility finding

LiteLLM 1.102.1 preserves the retained Responses-to-Chat behavior for ordinary
text, empty tool lists, function tools, streaming, upstream errors, and usage
including cached-input details.

One wire-shape change required a Router compatibility repair. A Responses
`reasoning` object is translated by LiteLLM 1.102.1 to an object-valued Chat
Completions `reasoning_effort`. Router Lite now canonicalizes only that object
shape back to the OpenRouter `reasoning` map at the final OpenRouter send
boundary. Scalar `reasoning_effort` remains unchanged for backward
compatibility, and an already-present `reasoning` field remains authoritative.

## Synthetic route matrix

A local chain used the real Router API forwarder and real LiteLLM 1.102.1
gateway against a fake OpenRouter HTTP server. Both retained GLM gateway
identities passed:

- canonical GLM route selected only Novita;
- GMICloud GLM route selected only GMICloud;
- both retained fallback disabled and required parameter support;
- both rewrote the gateway model to `z-ai/glm-5.3-flash`;
- empty tools and unsupported parallel-tool control were absent at the provider;
- reasoning reached the provider as the documented object map;
- function calls round-tripped into Responses output;
- streaming produced a completed Responses stream;
- cached-token usage survived translation; and
- synthetic upstream 401 and 429 statuses remained 401 and 429.

No OpenRouter request or paid model call was made by this test.

The candidate passed the complete Router test suite, the Node production
dependency audit, the hash-verified Python dependency audit, direct lock
validation, real LiteLLM startup, and the synthetic end-to-end route matrix.

This record does not claim that the installed managed Router virtual
